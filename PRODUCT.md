# Product

## Register

product

## Users

Auto-Tune is for Minecraft Paper server owners, administrators, and technically curious players. The primary public-site user is an admin deciding whether to install the plugin, configure the economy, connect to the cross-server price network, or validate a tuning change before using it on a live server.

## Product Purpose

Auto-Tune turns a static Minecraft server shop into an adaptive economy. The Java plugin records trades, recalculates item prices and spreads from supply-demand pressure, exposes an in-server dashboard, and can optionally report anonymized price ratios to the Rust price API for cross-server true prices. The public site should explain, document, and support that workflow without pretending that preview or simulated data is live production data.

## Brand Personality

Technical, plainspoken, and trustworthy. Auto-Tune should feel like a serious tool maintained by people who understand both Minecraft servers and market mechanics. The tone can be friendly, but claims should be concrete and tied to actual plugin behavior, docs, simulations, or API endpoints.

## Anti-references

Avoid generic AI/SaaS marketing patterns, inflated claims, fake live dashboards, decorative gradient-first sections, overstuffed navigation, and pages that say the same thing in different words. Do not present mock servers, simulated prices, or future features as if they are production network data.

## Design Principles

1. Keep the ecosystem legible: plugin dashboard, public site, Rust price API, and simulation lab each need a clear job.
2. Prefer operational clarity over hype: show what admins can install, run, configure, inspect, or test.
3. Be honest about data state: distinguish live API data, local simulation, generated examples, and planned work.
4. Make common admin paths short: install, configure, simulate, docs, network, API.
5. Use the public site as the front door, not as a pile of unrelated experiments.

## Accessibility & Inclusion

Target WCAG AA contrast, keyboard-reachable navigation and controls, visible focus states, semantic headings, readable tables on small screens, and no required motion for comprehension.
